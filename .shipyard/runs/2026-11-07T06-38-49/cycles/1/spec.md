# Cycle 1 spec: rename Crate Digger to Frisson

## What we are building

A pure rename PR. The product is currently called "Crate Digger" (display), `crate-digger` (npm scope, Docker image, repo slug) and `crate_digger` (session cookie). After this cycle the product is "Frisson" / `frisson` everywhere it is the product name, and nothing else changes: same routes, same schema, same data paths, same behaviour except the identifiers the brief explicitly asks us to rename.

The repo is an npm workspaces monorepo (root, `apps/api`, `apps/web`, `packages/shared`). The API runs TypeScript natively on Node 22 and imports `@crate-digger/shared` through the workspace symlink in `node_modules`, so the package rename and the import rename must land together, and the lockfile and symlinks must be regenerated by `npm install`, never by hand.

## What changes

- **Packages:** `frisson`, `@frisson/api`, `@frisson/web`, `@frisson/shared`; workspace dependencies and every import follow. `package-lock.json` is regenerated with `npm_config_nodedir=/opt/node22 npm install` and must contain no old name and no version drift.
- **API identifiers:** cookie `frisson_session`, HMAC fallback label `frisson-session` (logs every user out once, accepted by the brief), health `service: 'frisson-api'`, plus the test fixtures (temp dir prefixes, multipart boundary, test admin password).
- **Web:** `<title>Frisson</title>`, the App.vue header link and all 7 `document.title` strings.
- **Docs, Docker, CI:** README heading (emoji kept), SPEC title and tree root, DEPLOY title, ADR 0001 and 0003 text, Dockerfile usage comments and the CI image tag `frisson:ci`.
- **Tooling:** `.shipyard` goes into `.prettierignore` so `format:check` stays green once the run artifacts are committed.

## What deliberately does not change

- `crate.db`, `DATA_DIR`/`DATABASE_PATH`/`COVERS_DIR`, `/data` and the Compose volume `crate-data`. Renaming any of these would orphan the production database and covers.
- `compose.yaml` is untouched and gets no top-level `name:`. The Compose project name comes from the checkout directory, which stays `crate-digger`, so the volume prefix stays the same.
- The GitHub clone URL and `cd crate-digger` in `docs/DEPLOY.md` (lines 60 and 61). The repo is not renamed in this PR, so those are the only allowlisted hits for AC1.
- `apps/api/drizzle/**` (migration SQL and snapshots) and the domain word *crate* (CrateBox, CrateView, CratesView, CrateSettings, the crates table, `crate_sort_by`, crate-backup).
- The B-Side shared crates feature is out of scope.

## How the work is split

| Task | Owns | Depends on |
|------|------|------------|
| T1 manifests | 4 package.json files, `packages/shared/src/sorting.ts` (comment), `package-lock.json`, `.prettierignore` | none |
| T2 api | 11 `apps/api/src` files and 8 `apps/api/test` files | T1 |
| T3 web | `apps/web/index.html` and 32 `apps/web/src` files | T1 |
| T4 docs, Docker, CI | README, SPEC, DEPLOY, ADR 0001 and 0003, Dockerfile, ci.yml | none |

T1 and T4 run first in parallel; T2 and T3 run in parallel after T1, because their typechecks resolve `@frisson/shared` through the symlink that T1's install creates. No two tasks share a file. The file lists come straight from the survey inventory and a live case-insensitive grep, which agree (64 files including the lockfile).

## Done means

All 12 acceptance criteria hold. The final gate runs `format:check`, `lint`, `typecheck`, `test` and `build` from the root (all exit 0), and the AC1 grep returns only DEPLOY.md lines 60 and 61.
